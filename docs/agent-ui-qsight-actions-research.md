## Corrected purpose and implementation summary

Rakazo owns conversation, project selection, context and presentation. QSight owns canonical hierarchy, commercial records, sources, interpretation, deterministic money, change approval and audit. Chat artifacts are transport copies, not a second authoritative commercial document store (R `docs/agentic-ui-invariants.md:29`, `packages/adapters/src/project-intake-staging.ts:59`; P `server/intake.py:613`).

The agreed PM creation unit is claim + sub vendor + empty work package, **not a global prohibition on claim-only product APIs**. PM provisioning attaches an agent to an existing project; package creation is a later approved business action. QSight keeps independent setup and legacy reviewed-publication paths (R `docs/pm-intake-flow.md:9`, `apps/api/src/project-manager.ts:19`; P `docs/invariants.md:19`; A+ `server/mcp_pilot.py:350`).

One attachment send stages one manifest/intake; one folder per intake is an intended interaction, not a database law. The bridge currently uses filenames as relative paths and accepts only 10 files / 48 MiB each / 64 MiB total; QSight permits 500 files / 2 GiB total with the same per-file cap. Do not promise arbitrary folder upload or silently split a folder (R `packages/adapters/src/project-intake-staging.ts:56`; P `server/folder_imports.py:25`; A `docs/agent-intake.md:33`).

Staging is durable background work after message persistence. Success posts a receipt message but does not start or complete an autonomous review conversation. `inspectionContext` belongs to the initiating message/turn path, **not a durable intake-ID receipt**: the stage handler's success text omits the intake ID. The PM may recover it through the bounded open-intakes tool (R `apps/api/src/routes/threads.ts:181`, `packages/adapters/src/background-job-handlers.ts:150`, `apps/api/src/thread-target.ts:522`; A+ `server/mcp_pilot.py:306`).

Read tools are pre-trusted; newly provisioned PM writes default to approval. Reprovisioning preserves previously explicit trust for allowed tools, so “all writes always prompt” is too strong. MCP bearer authorization itself does not prove a human approved a call (R `packages/core/src/plugin-catalog.ts:38`; A `docs/agent-plane-mcp-pilot.md:93`). PM tokens are read + scaffold, not hierarchy-write or publication grants (A `server/agent_api.py:199`).

PM discussion/correction instructions and adapter staging are source implementations. Rich review cards and human publication inside chat remain incomplete. R has a receipt signer helper; P+ has verifier/admission/HTTP/publisher source. These pieces do not constitute the designed authenticated card, actor-delegation/admission handshake or a working cross-repo journey (R `apps/api/src/publish-receipt.ts:12`, `docs/trusted-publish-receipt.md:1`; P+ `docs/publication-api.md:1`).

Published change-order documents create **draft** change revisions. Printed approval is evidence; only QSight's explicit impact-bound approval changes the reference. Space membership is not QSight approval authority; owner mapping/delegation is unresolved. No deployment state was inspected (P `server/intake.py:619`, `server/package_context.py:343`; R `docs/pm-intake-flow.md:47`).
